# TimeShift

Помодоро-таймер для macOS, живущий в строке меню. Классический цикл 25/5/15 с ручным запуском этапов, ретро-логированием пропущенных промежутков и дневным «банком» перерывов.

## Возможности (v0.3)

- Таймер в трее (`🍅 24:31`) с меню: старт/пауза/смена этапа, парковка задач, глобальный хоткей `Cmd+Shift+Space`.
- Конечный автомат дня поверх журнала событий: любое действие валидируется, превращается в событие и применяется через свёртку (fold) — состояние всегда воспроизводимо из журнала.
- Ретро-разрывы: если между этапами прошло время, приложение предложит задним числом залогировать разрыв (`NeedGap`).
- WAL-first: события пишутся в JSONL-журнал (`~/.timeshift/wal/`) с fsync и ролловером по дням. Журнал — единственный источник истины, всё остальное опционально.
- Подключаемое хранилище-реплика (v0.3): только файлы (по умолчанию), локальный SQLite (`~/.timeshift/timeshift.db`) или Postgres — идемпотентность через таблицу `applied_events`, переподключение с ретраями. Реплика недоступна — ничего не теряется, журнал догонит.
- План дня (v0.2–v0.3): из «☀️ Сегодня» Obsidian через Local REST API — импорт чекбоксов, секции работа/личное, оценки в помидорках, встречи, двусторонний синк отметок (конфликт — отказ от записи, при закрытом Obsidian очередь догоняет). Модуль Obsidian опционален: без него задачи и встречи добавляются вручную прямо в приложении.
- Дневной фокус-лог «⏱ Фокус-логи/ГГГГ-ММ-ДД.md» пишется в хранилище при закрытии дня — сводка, сессии, прерывания, план/факт (LLM-обзор — в v0.4).
- UI на React: экраны «День», «План», «Парковка», «Настройки» (включая выбор хранилища и тумблер Obsidian); диалог разрыва с повтором исходной операции после ретро-логирования.

## Стек

- **Ядро:** Rust, Tauri 2
- **UI:** TypeScript, React, Vite
- **Хранилище-реплика (опционально):** PostgreSQL 17 или SQLite; по умолчанию — только WAL-файлы

## Установка

Готовые сборки macOS публикуются в [Releases](https://github.com/UnMatty/TimeShift/releases): скачайте `TimeShift_<версия>_universal.dmg` — универсальный образ и для Apple Silicon, и для Intel. Откройте его и перетащите приложение в Applications.

Приложение распространяется без подписи Apple, поэтому при первом запуске macOS может предупредить о неизвестном разработчике: нажмите на `TimeShift.app` правым кликом и выберите «Открыть».

Новый релиз собирается автоматически: workflow `.github/workflows/release.yml` срабатывает на пуш тега `v*` (или вручную из вкладки Actions) и публикует `.dmg` через [tauri-action](https://github.com/tauri-apps/tauri-action).

## Сборка и запуск

```bash
npm install
npm run tauri dev    # режим разработки
npm run tauri build  # сборка .app / .dmg
```

Тесты и линт ядра:

```bash
cd src-tauri
cargo test
cargo clippy
```

## Конфигурация

Конфиг лежит вне репозитория: `~/.timeshift/config.toml` — либо через экран «Настройки», либо руками. Секреты (пароль БД, API-ключи) живут только в этом файле; предполагается переезд в macOS Keychain.

```toml
[db]
# Подключаемая реплика журнала. "none" (по умолчанию) — только WAL-файлы;
# "sqlite" — локальный файл; "postgres" — существующий контейнер.
backend = "none"
# url = "~/.timeshift/timeshift.db"                          # для sqlite
# url = "postgresql://timeshift@localhost:5432/timeshift"    # для postgres

[vault]
# Подключаемый модуль Obsidian (Local REST API): план из «☀️ Сегодня»,
# синк чекбоксов, фокус-логи. Без ключей или с enabled = false приложение
# полноценно работает без Obsidian — план ведётся вручную.
enabled = false
# api_url = "https://127.0.0.1:27124"
# api_key = "<ключ плагина Local REST API>"

[llm]
# Заготовка v0.4: OpenAI-совместимый endpoint вечернего обзора.
```

Конфиги до v0.3 (только `[db] url` с Postgres-строкой) продолжают работать без правок: отсутствие `backend` при заданном `url` означает Postgres-репликацию, как раньше.

## Архитектура

Ключевая идея: состояние дня — это свёртка журнала WAL-событий. Операции UI/трея не мутируют состояние напрямую, а валидируются и порождают события; запись в WAL и свёртка — единственный путь изменения состояния. Репликатор доносит журнал до подключённого хранилища (SQLite или Postgres), поэтому источник истины всегда один — журнал: реплика отстать может, опередить — нет.
